
# KODA.md — Инструкционный контекст проекта

## 1. Обзор проекта

**Название:** Boiler Safety Monitor — веб-демо

**Назначение:** Автономная (standalone) интерактивная демонстрация системы видеомониторинга
промышленной безопасности. Приложение имитирует работу компьютерного зрения: проигрывает
демонстрационное видео и по заранее заданному временному расписанию «генерирует» события
распознавания текста, измерения диаметра и подсчёта объектов. Реального бэкенда, модели ML
или базы данных **нет** — вся логика симуляции живёт в браузере.

**Язык интерфейса:** русский (RTL-разметка отсутствует, `lang="ru"`).

**Архитектура:** классический статический сайт из двух страниц без сборщика и без фреймворка.

```
Браузер (index.html / reports.html)
   ├── js/scenarios.js  → декларативная конфигурация сценариев (источник данных)
   ├── js/app.js        → логика мониторинга: таймеры, события, управление видео
   ├── js/reports.js    → мок-данные отчётов + рендеринг таблиц и графиков
   └── server.py        → статический HTTP-сервер с поддержкой Range-запросов
```

**Технологический стек:**

| Слой | Технология | Способ подключения |
|------|-----------|--------------------|
| Вёрстка | HTML5, Bootstrap 5.3 | `lib/bootstrap/` (vendored) |
| Иконки | Bootstrap Icons | `lib/bootstrap-icons/` (vendored) |
| Графики | Chart.js 4.4.1 | **CDN** `cdn.jsdelivr.net` (только `reports.html`) |
| Шрифты | Inter, JetBrains Mono | **CDN** Google Fonts |
| Логика | Vanilla JS (ES6+, без модулей) | обычные `<script>`-теги |
| Стили | CSS + CSS-переменные | `css/style.css` (647 строк) |
| Сервер | Python 3 stdlib (`http.server`) | `server.py`, зависимостей нет |

**Ключевой факт:** нет `package.json`, `requirements.txt`, `node_modules`, сборки, линтера и тестов.
Всё запускается «как есть».

## 2. Сборка и запуск

### Сборка
Отсутствует. Никаких шагов установки зависимостей выполнять не нужно.

### Запуск

```bash
python server.py
```

Затем открыть в браузере: **http://localhost:8080**

Дополнительная страница отчётов: **http://localhost:8080/reports.html**

### Остановка
`Ctrl+C` в терминале, где запущен сервер.

### Тесты, линтинг, проверка типов
**TODO:** в проекте отсутствуют тесты, линтер и конфиги проверок. При изменении кода
проверка выполняется вручную в браузере:

1. Запустить `python server.py`.
2. Открыть `http://localhost:8080`, нажать «Старт» — видео должно играть, события — появляться в таблице.
3. Проверить «Пауза»/«Стоп» — статус-бейдж должен переключаться (Остановлен → Активен → Приостановлен).
4. Кликнуть по бейджу сценария в навбаре, сменить сценарий в модальном окне, нажать «Применить».
5. Открыть `reports.html` — проверить, что графики Chart.js отрисованы (нужен доступ в интернет из-за CDN).
6. Открыть консоль браузера (F12) — ошибок быть не должно.

### Конфигурация сервера
В `server.py` жёстко заданы:
- порт `8080` (`HTTPServer(('', 8080), ...)`);
- корень раздачи — каталог, где лежит сам `server.py` (`SERVE_DIR`);
- `MIME_OVERRIDES` — принудительные типы для `.webm`, `.mp4`, `.ogg`, `.ogv`.

## 4. Модель данных: сценарии

### `SCENARIOS` (`js/scenarios.js`)

Сейчас объявлено **три** сценария:

| Ключ | Видео | Смысл |
|------|-------|-------|
| `ocr` | `video/ocr.webm` | Распознавание текста на конвейере (дата, серийные номера) |
| `diameter` | `video/diameter.webm` | Измерение диаметра объектов (px → мм) |
| `registered` | `video/Registered.webm` | Подсчёт объектов по типам за цикл |

Форма записи:

```js
const SCENARIOS = {
    <ключ>: {
        name: '<отображаемое имя>',
        video: 'video/<файл>.webm',
        events: [
            { time: 'м:сс', message: 'Текст события', zone: 'Камера 1',
              severity: 'info|success|warning|danger', type: 'event|alert' },
            // ...
        ]
    }
};
```

Соглашения:
- `time` — строка `'м:сс'`, парсится `parseTime()` в секунды; отсчитывается **от wall-clock**
  (`Date.now() - scenarioStartTime`), а не от `video.currentTime`.
- `type: 'event'` → попадает в таблицу «События»; любое другое значение → в «Уведомления».
- `severity` должен совпадать с CSS-классом `severity-<значение>` из `css/style.css`.
- События в массиве должны быть отсортированы по возрастанию времени — `checkScenarioEvents()`
  идёт по ним линейно через `nextEventIndex` и останавливается на первом «ещё не пришедшем».
- Когда все события выбраны, мониторинг автоматически останавливается (`stopMonitoring()`).

### `REPORT_DATA` (`js/reports.js`)

Отдельный мок-объект для страницы отчётов. **Содержит только `ocr` и `diameter`** —
сценарий `registered` в отчётах отсутствует. Поля: `name`, `sessions`, `totalEvents`,
`alerts`, `avgDuration`, `lastRun`, `events[]`, `stats{}`, а также массивы истории для графиков
(`confidenceHistory`, `diameter1History`, `diameter2History`, `deviationHistory`, `statusCounts`).

## 5. Правила разработки

### Стиль кода
- **JavaScript:** ES6+, `const`/`let`, стрелочные функции, шаблонные строки, `map`/`filter`.
  Отступ — 4 пробела. Двойные кавычки в Python, одинарные кавычки в JS-строках путей.
  Точка с запятой обязательна.
- **Глобальное состояние:** единственный объект `STATE` в `js/app.js`. Новые поля добавлять в него,
  а не создавать разрозненные глобальные переменные.
- **Доступ к DOM:** короткий помощник `const $ = (sel) => document.getElementById(sel);`
  и предсобранное хранилище `els`. Повторно использовать их, а не писать `document.querySelector` в каждом месте.
- **Рендеринг:** генерация HTML через `.map(...).join('')` и присваивание `innerHTML`.
  Так сделано намеренно (демо, данных мало) — придерживаться того же подхода.
- **Именование:** `camelCase` для функций и переменных, `SCREAMING_SNAKE_CASE` для констант
  (`STATE`, `SCENARIOS`, `REPORT_DATA`, `MIME_OVERRIDES`, `SERVE_DIR`).
- **Идентификаторы HTML:** kebab-case (`btn-start`, `video-seek`, `stat-fps`, `events-table`).
  JS-ссылки на них завязаны по имени — при переименовании синхронно править `js/app.js`.
- **Python:** 4 пробела, класс `VideoRequestHandler(BaseHTTPRequestHandler)`, docstring в начале файла,
  `snake_case` для методов. Обработка `BrokenPipeError`/`ConnectionResetError`/`OSError` обязательна
  при записи в сокет — клиент обрывает соединение при перемотке.

### Разделение ответственности
- **Данные → `js/scenarios.js`.** Тексты событий, тайминги, зоны, уровни, пути к видео менять **только там**.
- **Логика → `js/app.js`.** Не захардкоживать тексты событий в логике.
- **Вёрстка → `index.html` / `reports.html`.** Кастомные стили → `css/style.css`;
  layout-специфичные правки высоты допускаются инлайном в `<style>` страницы (так уже сделано).
- Не подключать npm-пакеты и сборщики — проект принципиально без них.

### Как добавить новый сценарий
1. Положить видеофайл в `video/` (предпочтительно `.webm`).
2. Добавить объект в `SCENARIOS` в `js/scenarios.js`.
3. Добавить `<option value="...">` в `<select id="modal-scenario-select">` в `index.html`.
4. *(Рекомендуется)* Добавить запись в `REPORT_DATA` в `js/reports.js` и соответствующую
   разметку секции в `reports.html`, иначе сценарий не попадёт в отчёты.

### Как изменить отчёт
- Числа и события — в `REPORT_DATA`.
- Новые графики — новая функция `renderXxxCharts()` + `<canvas id="...">` в `reports.html`
  + вызов из `renderCharts()`. Экземпляры хранить в объекте `charts`, чтобы избежать
  повторного создания Chart на одном canvas.

### Известные особенности и «долги» (учитывать при правках)
- `STATE.currentScenario` инициализирован значением `'behavior'`, которого нет в `SCENARIOS`;
  его перезаписывает `loadScenario('ocr')` в `init()`. Значение-заглушка, но в `startMonitoring()`
  есть резервная ветка `'video/1.webm'` — устаревший код.
- В `index.html` присутствуют элементы **без обработчиков** в JS: `#btn-fullscreen`,
  `#video-status-badge`, `#status-dot`, `#status-text`, `#auto-load-video`.
  Статус в шапке видео и полноэкранный режим фактически не работают; статус управления
  пишется в `#monitoring-status`.
- `README.md` и `AGENTS.md` описывают **два** сценария (`ocr`, `diameter`) и упоминают `.mkv` —
  документация отстаёт от кода (сценариев уже три, формат — `.webm`/`.mp4`). При правках
  синхронно обновлять оба файла.
- `reports.js` использует глобальный `Chart` из CDN: без интернета страница отчётов
  выдаст ошибку и графики не отрисуются. `index.html` полностью автономен.
- `severity`-бейджи завязаны на CSS-классы: допустимые значения `info`, `success`, `warning`, `danger`.
- Статистика (FPS, GPU, люди, инциденты, клипы, зоны) — **случайные числа** из `updateStats()`,
  обновляются раз в секунду; это ожидаемое поведение демо, а не баг.
- Перемотка (`#video-seek`) меняет только `video.currentTime` и **не** синхронизирует
  расписание событий — события привязаны к реальному времени с момента «Старт».

### Практики коммитирования
История git ведёт коммиты в формате **английского императива**, коротко и по сути,
иногда с префиксом-областью:

```
Add Registered scenario with object counting events and Registered.webm video
UI: move scenario selector to navbar, show scenario name in video panel
Navbar: remove title, use home icon (bi-house-fill) with hover effect
Fix layout: video card fits viewport height with flexbox
```

Стиль: одна строка, без точки в конце, начинался бы с «Add / Fix / Update / UI: / <Область>:».

### Безопасность
- `server.py` — только раздача статики из `SERVE_DIR`; `translate_path()` нормализует путь
  через `posixpath.normpath` и отбрасывает query/fragment. **Не ослаблять** эту логику
  и не добавлять исполнение кода на сервере.
- Сервер слушает `''` (все интерфейсы) на порту 8080 — это демо-режим; не использовать
  как продакшн-сервер и не размещать в нём реальные данные.
- Не добавлять в репозиторий секреты, токены и реальные записи с камер.

консоль браузера без ошибок → видео играет, события появляются, графики отрисованы.
